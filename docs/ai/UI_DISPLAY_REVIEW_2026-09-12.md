# UI 显示复核与下一轮实施任务

日期：2026-09-12。基线 HEAD：`0ede445`，包含工作树中尚未提交的图标按钮语义调整。本轮只审查、补充文档，不修改生产界面，不代提交其他人的代码。

## 结论与证据边界

字体、线性图标、玻璃按钮和动效已经有共享实现，不应再次整体换皮。下一轮重点是：**短窗口可用面积、信息重复、表格阅读、详情区和状态反馈**。以下区分可见现象与设计建议，不能把建议写成已确认的运行故障。

- 新生成的离屏图：[待归类完整壳层](../design/reviews/2026-09-12-display/media-shell.png)、[任务完整壳层](../design/reviews/2026-09-12-display/tasks-shell.png)、[设置错误状态](../design/reviews/2026-09-12-display/settings-errors.png)、[首页独立内容区](../design/reviews/2026-09-12-display/overview.png)。图像未经修改，均为 RenderHarness 测试数据。
- Shell 图由测试程序直接挂载页面，顶栏仍显示“首页”；这不能作为生产导航标题错误的证据。设置截图为 744×460 DIP 内容区；不能把文件名 1040×700 当作实际内容尺寸。
- 待归类 1040×700 壳层中可见整页滚动，批量底栏不在首屏。代码 `MediaCenterView.ApplyResponsiveLayout` 明确在页面高度 `<620` 或过期提示出现时启用 page fallback scroll。这是当前有意的降级策略，但仍有使用成本，并非已经复现了旧的“数据漂移”。
- 任务图底部可见部分行并不能证明末条不可达；必须到达真实滚动终点验证。此前用户视频中的空表、漂移和末行问题仍需真实 Playnite 复验，本轮不宣称已解决或再次复现。
- 设置图顶部错误区、多层外边距占据接近半个内容区，表单首屏仅容纳少量字段；首页独立短内容区中，概览与统计占据首屏，工作内容在下方。这两项是本轮直接可见的改进点。
- 项目规则引用的 `GameSaveCenter.AcrylicFork/.../Design/` 在当前工作树不存在。实施者应先恢复可追溯的 Demo 基准引用；不要自行用其他设计风格替代。当前共享生产资源与既有用户确认截图可用于保持一致性。

## 实施规则

按下面顺序逐项交付。UI 显示任务不需要重写 Worker、业务命令或数据契约；每项保留真实数据、取消/错误语义、虚拟化、键盘和自动化名称。已有当前游戏选框和滚动条外观继续复用。

禁止用减小全局字体、负 Margin、覆盖裁切、固定底部空白、关闭虚拟化、滚动时反复 Refresh/UpdateLayout 或给列表行加动画解决布局。每项先展示同尺寸前后截图，再记录实际几何与人工验收边界。

## 第一批：优先处理最容易看到的改善

### D12-01 待归类短窗布局收口（高优先级）

入口：`Views/MediaCenterView.xaml`、`.xaml.cs` 的 `MediaInboxPageScrollViewer`、`MediaInboxInfoBand`、`MediaInboxTableFrame`、`ApplyResponsiveLayout`。

1. 在实际页面高度 520–620 DIP 下提供紧凑布局；先压缩统计摘要和重复的“待归类媒体 + 数量”独立色带，把标题与数量合并到表格工具栏。
2. 页面维持 Auto 摘要/导航、* 主体；表格卡片维持 Auto 工具栏、* DataGrid、Auto 批量底栏。详情走现有窄窗入口，宽窗独立滚动。
3. 批量底栏固定显示选中数量及主要归类操作；建议说明和历史入口用次级信息或折叠区。所有被收起操作必须有明确入口，不能直接删除。
4. 先计算紧凑布局的最小可用高度，再缩小整页滚动降级的触发范围；不能直接删除现有 fallback，否则过期提示可能再次把表格压到零高度。低于支持的内容高度时保留可访问降级。

验收：1040×700、1100×720 壳层下，正常状态至少完整显示 5 行，主要批量操作无需滚动页面可达；过期/离线提示打开后仍有非零可读视口。验证 0/1/6/400/2000 条、长原因、全部主题；拖滑块到底和 Ctrl+End 后真实末条完整可见。报告中区分窗口尺寸、PageHost 尺寸、DataGrid 内容视口尺寸。

### D12-02 设置页缩短错误摘要（高优先级）

入口：`Settings/GameSaveCenterSettingsView.xaml`、`.xaml.cs` 的 `SettingsHeader` 与校验提示。

1. 短窗隐藏装饰性 SETTINGS 眉题，缩小外壳与卡片重复边距；保留设置标题与当前类别。
2. 多项错误改为“有 N 项设置需要修正”摘要 + “定位首个错误”；详细错误放到对应字段旁，并提供可展开错误列表。不要在页头同时显示拼接长错误和重复错误徽标。
3. 普通短窗摘要目标不超过两行，但不能靠固定 Height 裁掉文本；高 DPI/更窄窗口允许自然扩展。保存阻断、定位、字段校验保持真实有效。

验收：同一 744×460 DIP 内容区、同样三项错误，相比基线至少多显示一个完整字段；键盘可定位全部错误，长路径与高 DPI 不重叠，错误不能仅剩 Tooltip。

### D12-03 任务页统计与筛选紧凑化（中高优先级）

入口：`Views/TaskCenterView.xaml`、`.xaml.cs` 的 `TaskSummaryPanel`、筛选栏和 `TaskWorkspaceLayout`。

短高度时把四个统计项收敛为单行数值+标签，辅助说明放 Tooltip；保留现有“更多筛选”与条件摘要。合并列表标题、加载计数、重试入口的多余垂直留白。不要缩小表格字体或改变行虚拟化。

验收：1040×700、详情关闭时，相同数据比基线至少多显示两条完整任务；搜索宽度、当前筛选、清除筛选仍可见可用。详情开启和关闭均验证真实末条，而非只看截图底部的半行。

### D12-04 首页首屏优先显示工作内容（中优先级）

入口：`Views/OverviewView.xaml`、`.xaml.cs`。

短窗把提示 Hero 改为紧凑提示条，保留最重要的一条异常与对应操作；统计保留全部入口但减少说明换行与装饰高度。当前游戏卡、首页工作台和壳层重复的备份操作按作用域明确“当前游戏/全部游戏”，选择主要展示位置，避免同一屏多处同等强调。

验收：原图对应 956×480 DIP 内容区首屏能看到工作区标题和至少一项实际内容；无异常、无当前游戏、有异常均有明确下一步。不得改变“全部备份”的作用范围。

## 第二批：表格和详情的阅读质量

### D12-05 表格主次与长文本（中优先级）

入口：`Themes/Redesign.xaml`、`Themes/Typography.xaml`，Media/Task/Maintenance 的列模板。

核对运行时实际 FontWeight 来源，尤其媒体与诊断行；正文日期、类型、来源、路径用 Regular，仅名称或主要字段按需要强调。继续保留透明表头，不恢复整块深色表头。长路径/原因采用省略号、完整 Tooltip 和可复制详情；日期与状态列给稳定宽度，剩余空间优先给文件/游戏名。最小宽度不足时保留真正可用的横向滚动，不能强制压扁全部列。

验收：长中文名、长英文路径、200% DPI、横向滚动两端、选中与未选中均可读；排序热区和列拖拽仍有效。文字粗细是阅读建议，未认定为字体渲染故障。

### D12-06 任务失败详情去重（中优先级）

入口：`Views/TaskCenterView.xaml` 的完整详情、`TaskInspectorErrorCard` 和 `TaskDetailActions`。

当前代码同时绑定普通详情与独立 ErrorMessage/ErrorCode 区，可能重复同一个错误。失败态顶部只放用户可理解的原因和处理建议，错误码、任务 ID、原始详情放“技术详情”折叠区；复制命令仍复制完整诊断信息。普通 Detail 与 ErrorMessage 相同时不重复显示，不同且有信息价值时保留。

验收：长错误无需滚动大量重复文本才能找到操作；成功、取消、待人工处理的恢复任务不能套用普通失败重试文案。保留安全重试既有条件，不擅自更改命令执行逻辑。

### D12-07 媒体预览状态准确化（中优先级）

入口：`Views/MediaCenterView.xaml`、现有缩略图/预览状态绑定。

无选择显示“选择媒体查看预览”；选中后分别呈现加载中、预览成功、不支持、文件不可访问、加载失败，不能继续提示用户选择。测试截图选择了 shared-1.png 却仍显示通用占位，但该路径是测试数据，因此真实失败分支需先复现后定性。文件名、打开媒体/目录置于预览附近，建议与批次历史为次级区。

验收：图片、录像、不存在路径、切换选择及过期异步结果；旧预览不得覆盖新选择，缓存与加载并发保持有界。普通状态变化不重建 DataGrid。

## 第三批：可感知反馈与验收工具

### D12-08 状态反馈分级（中优先级）

入口：现有 EmptyState/加载/错误控件与各页绑定，先盘点复用组件再新增。

区分首次加载、后台刷新、无数据、筛选无结果、离线缓存与请求失败。后台刷新保留已有行和选择，仅显示轻量更新标记；无结果给“清除筛选”，离线缓存显示时间与重连状态。不要让零条计数兼任“读取失败”。避免每页重复展示多个同义离线提示。

验收：状态图至少各一张；快捷刷新不闪白、不整表淡出、不丢选择和滚动位置；状态不靠颜色单独传达。

### D12-09 动效验收与可访问性（较低优先级）

复用 `GscMotion` 与 `MotionTokens.xaml`，不再增加一套动画。只检查刷新进行中反馈、详情展开、按钮按下和焦点是否连续自然。表格滚动与行容器保持静态，错误提示不抖动，关闭动画与高对比度直接进入终态。

本轮 Shell 性能探针记录一次最大帧间隔约 77ms；这是测试环境单次数据，不能认定真实宿主卡顿。后续在宿主记录重复采样再决定是否优化，不能仅凭截图宣称“丝滑”。

### D12-10 修复视觉验收入口并补齐宿主证据（交付前必做）

入口：`tests/GameSaveCenter.RenderHarness/Program.cs`、`scripts/render-qa.ps1` 与设计基准文档。

1. 本轮完整 render-qa 编译成功，但运行退出 -1，未生成最终报告；保留部分截图不能冒充全流程成功。定位终止原因，并按阶段写诊断/及时落盘，使异常退出也能知道最后完成的 probe。
2. 单独 shellqa 新建目录运行时，浅/深色背景输出目录未创建导致失败；手动创建 `theme/light`、`theme/dark` 后同一程序通过。实现入口应自行创建目录，使首次运行不依赖旧产物。
3. 修正 Shell 场景的导航/标题测试状态，让截图真实反映所审页面；测试假数据中“成功但进度 24%”等状态应改为一致的正常样例，另留明确标注的异常样例。
4. 找到当前可用 Demo 资源/历史版本并更新引用；源码、包和真实安装目录核对一致后，在真实 Playnite 测试窄窗、DPI、用户主题和连续滚动。

验收：空目录首次运行报告成功，完整过程有退出状态和阶段信息；真实滚动录屏覆盖此前空表/漂移/末行场景。RenderHarness 通过只能表述为离屏通过。
