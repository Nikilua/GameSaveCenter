## 给执行 AI 的提示词

在 GameSaveCenter 当前分支实施本文件 A、B、C。先按 AGENTS.md 读取项目记忆、工作日志、Git 状态与上游。核对并行任务、最新源码和证据，已经满足的条目引用验证结果。共享文件有在途修改时在独立工作树开发，合入时保留对方修改；按批提交，只暂存本批文件。每批先跑能覆盖以上具体验收场景的测试，再同步工作日志、项目记忆，并沿用近期风格用中文提交。

UI 对照同级 AcrylicFork 的 Demo 与生产共享资源，按仓库 WPF 技能检查双主题、窄窗、键盘、读屏语义、虚拟化与关闭动画。使用隔离配置与合成数据，在可见 Playnite 中验证本批代表操作。记录哪些是实机观察、哪些是自动化；可复用在途走查的数据与环境安排，避免两个任务争用同一进程、管道或测试输出。

每批在最终交付 SHA 上实际运行仓库根目录的 GameSaveCenter-一键构建安装运行.cmd，核对它调用 GameSaveCenter-Run.cmd。等入口进程退出，采集其真实退出码；核对构建、测试、发布、打包、六个安装程序集身份及隔离宿主启动。确认首页能经私有管道读到本次 Worker，核对安装、数据目录与源码 SHA。分别报告通过、失败和跳过数，绑定本次 TRX、安装报告和运行记录。

推送当前分支的上游，核对远端包含交付 SHA，并查询 .github/workflows/windows-build.yml 对应完整 head_sha 的 run。持续跟进基线 SDK 与 SDK 10 两个适用 job 至 completed/success。失败时定位首个失败步骤、保留诊断、修复并提交；源码或合入发生变化后，在新 SHA 上重新执行完整本地入口和双 SDK 验证。只在同一 SHA 的两侧门禁通过且本批场景得到验证后标记完成。外部权限阻塞时写明证据和待验项。沿用现有测试、跳过策略和工作流。纯文档阶段依仓库规则做内容、链接及差异校验，避免 CI 记录循环。

每批开始前、重试前和收尾时检查系统盘及仓库盘余量，并盘点 .tmp 和 artifacts。本批已失效的构建副本、旧测试 scratch、重复 ZIP、过期离屏输出要及时回收。先逐项目核对生成来源、进程占用、文档引用和 Git 身份；解析后的绝对路径必须在仓库这两个目录内部，路径链及目标内容无重解析点，且不含跟踪文件或工作树。对确认的具体目标使用 PowerShell Remove-Item -LiteralPath ... -Recurse -Force。保留最新包、当前验收及仍需诊断的证据；并行任务产物和仍在使用的隔离环境归原任务管理。删除后核对路径消失，记录逻辑字节数、卷可用空间实测变化和保留原因。生成物留在本地。

每批交付回复给出完成项、可见变化、最终 SHA、上游分支、本地入口退出码与测试统计、GitHub run/job 链接、宿主验证范围、清理结果及剩余问题。
