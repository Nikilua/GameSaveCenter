## 主要发现与下一步

### R1 高优先级：校对页明显黑字仍通过门禁

现有暗色校对截图中，数字行、主/次按钮文字、开关文字、三个状态徽章文字为黑色；暗背景上明显不清楚。截图来自生产资源开发夹具，不能直接扩大为所有真实宿主页面都黑字，但足以否定该夹具已完整证明深色可读性的说法。

`Typography.xaml` 中 `GscTypographyNumeric` 未设置 Foreground；校对 View 中 Numeric 未局部设置前景，徽章子 TextBlock 也未显式取得语义色。按钮文本的黑色需继续追踪最终模板值/继承，不能把所有问题草率归到同一个 Setter。

`RunFinesseProbeOnly` 只运行 palette ContrastGuard、渲染 PNG、记录 Items.Count/Buttons/CaptionOpacity，然后写 OK；它没有检查每个显示文本的最终 Foreground 与实际背景，也没有操作按钮五态。下一轮 Q00-01/02/04 必须先修有效颜色与负例门禁；样式修生产共享源，不仅覆盖夹具。

### R2 高优先级：状态色按图形阈值检查，却用作小字

ContrastGuard 的 Success/Warning/Info/Error 阈值为 3.0；保存的 Light 报告中 Success=4.078、Warning=4.371（相对 palette.Background），都低于普通文字目标 4.5。生产 `SaveCenterView.xaml` 的差异列表在 446/454/485 行附近以 11 DIP 使用这些语义色作文字，不能仅按图形对比门槛签收。

真实文字有不同阅读表面，不能仅凭上述 palette 比值断言每个实际实例失败；应对最终表面逐实例测量。当前报告也把 ControlStroke 的 alpha 忽略后用于相对 surface 对比，未全面组合渐变/透明度。Q00-03、Q03-08 补齐；普通文字采用 [W3C 4.5:1 原则](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，装饰边线另行判断。

### R3 中优先级：数字、四行与字体证据不完整

浅/深夹具的数值列在长计数右缘出现裁切，表格底部行空间紧，必须检查完整行与有效裁剪交集。报告 `ProbeRows:4`/`DataGrid rows=4` 只是数据数量，不是“四行完整可读”。目前无该夹具的几何负例，不应据此签署完整阅读面。

`AppendFontResolutionEvidence` 枚举硬编码候选字体，通过 `TryGetGlyphTypeface/CharacterToGlyphMap` 找首个可用字体，输出 `resolved`。这证明显式候选字形可用性，**不是实际 TextBlock 最终 GlyphRun 的字体解析**，也没覆盖系统补字。罕见字 unresolved 不能直接当作屏幕必然方框。Q00-04/05、Q01/Q02 分开补证。

### R4 中优先级：动效底座统一不等于动效生命周期完成

时长读取确已改进且有定向测试。可是 `AnimateEntrance` 仍明确设 Opacity=0 并从 0 入场；对于快速重入是否跳帧，需要调用路径和实际序列测试。`IsEnabled` 在入口判断系统设置并不自动清除已运行的动画。`GetMutableScaleTransform` 对 TransformGroup 的复用也需检查，不能从“实例独占”推导多次调用不会追加 Transform。

本轮未见针对全部入口的 100 次卸载/重入时钟释放或运行中关闭动画的新行为证据。这里属于待验证风险，未把它们写成已复现的全局用户故障。Q18 专门处理真实调用上下文、接管、释放与热切换。

### R5 中优先级：证据入口失效，部分“外部阻塞”可继续推进

`docs/design/reviews/ui-finesse-20260913/BASELINE.md` 的 7 个 Markdown 链接使用 `../../.tmp` 或 `../../artifacts`，从当前目录实际应回到仓库根四层。本轮修正链接，保留旧报告内容与实际采集时间，不改写其成功/失败历史。

`scripts/package.ps1` 按 dirty tree 停止是正常保护。`src.zip` 是用户文件，不应删除、移动、提交或临时忽略；但**基于已提交代码的干净 worktree**可以继续构建打包，不必把它长期当作无解宿主条件。真正的 Playnite 主窗口可见性、物理输入和呈现数据仍是独立待验收项。新 Luna 任务默认用 worktree，原始文件不受影响。
