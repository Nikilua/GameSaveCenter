# R04-06 清空与撤销（2026-09-17）

## 结论

R04-06 在当前生产搜索和普通文本编辑范围内已满足：搜索清空入口会保留/恢复输入框焦点，Esc 关闭游戏选框后回到游戏上下文按钮；普通 TextBox 继续使用 WPF 标准 SelectAll、Undo、Redo 和粘贴链，撤销不会进入业务危险命令。

## 现状核对与实现

- 最新生产代码已有各页面搜索清空处理：Shell、Dashboard、Trainer、Task 和 Media 的清空事件都对目标 TextBox 执行 `Clear`、`Focus` 和 `Keyboard.Focus`。本阶段没有重建搜索 VM、命令或选框，也没有从 `main` 带入旧实现。
- Dashboard 的“当前选择不在当前筛选结果中”提示原先只有 `GamePicker.ClearSearchCommand`，执行后焦点可能停留在按钮。现在保留该命令，同时绑定当前 `GameSearchTextBox` 作为 Tag 并复用 `OnClearTextBoxClick`；清空后事件标记为 handled，避免按钮事件继续冒泡。
- Shell 游戏选框清除按钮增加稳定的 `GameSearchClearButton` 名称，便于 UI 自动化/行为夹具定位；原有 `OnClearGameSearchClick` 和 `GamePicker.SearchText` 绑定不变。
- 普通编辑没有新增自定义 Undo 栈。测试通过 WPF `ApplicationCommands.SelectAll`、`ApplicationCommands.Undo` 和 `ApplicationCommands.Redo`，以真实 TextBox 的标准粘贴事件替换选区；Undo 后原文本及 9 字符选择区恢复，Redo 再现修改。Esc 的业务路由只关闭选框并恢复上下文焦点，不调用保存、恢复、删除或其他危险命令。
