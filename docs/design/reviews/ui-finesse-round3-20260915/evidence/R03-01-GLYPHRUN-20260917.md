## 任务边界

R03-01 要求在 WPF 绘制/排版输出中检查关键 `GlyphRun`/`Typeface`，同时保留“字体候选覆盖”和“最终落字”两种证据，不把无法获取的字形推定为命中。本项先复用现有 `TypographyDiagnostics.UiFontChain` 和 `FindCandidate`，没有更换生产字体链、嵌入新字体或改动页面布局。

## 实现

- `TypographyDiagnostics.CaptureGlyphRun` 使用同一字体链创建 WPF `TextFormatter`，调用 `TextLine.GetIndexedGlyphRuns()` 读取目标字符覆盖的实际排版运行，并记录 `GlyphTypeface` 家族、运行数、glyph 数、目标码点映射和 `.notdef` 情况。
- `FontCandidate` 仍只表示 `Typeface.CharacterToGlyphMap` 的候选覆盖；`GlyphRunCaptured` 只在捕获到实际 WPF 排版运行、最终字体映射到目标码点且没有 `.notdef` 时使用。
- 未捕获运行时只返回 `CandidateOnly` 或 `Unknown`；出现 `.notdef` 或最终字体无法映射目标码点时返回 `GlyphRunNotdefOrUnresolved`，不会把候选结果写成最终命中。
- RenderHarness 的 `finesseprobe` 对关键样本逐项输出 `FontCandidate` 与 `GlyphRunEvidence`，并保留额外箭头/emoji 样本用于回退观察。

## 关键样本证据

clean commit 下 Light/Dark 两次 `finesseprobe` 结果一致，均为 `runs=1`、`glyphs=1`、`finalTypefaceHasCodePoint=True`、`notdef=False`：

| 样本 | 文本/码点 | 候选覆盖 | 最终 GlyphRun 字体 | 证据等级 |
| --- | --- | --- | --- | --- |
| 中文 | `存` / U+5B58 | `Noto Sans SC` | `Noto Sans SC` | `GlyphRunCaptured` |
| 英文 | `S` / U+0053 | `Segoe UI Variable Text` | `Segoe UI Variable Text` | `GlyphRunCaptured` |
| 数字 | `9` / U+0039 | `Segoe UI Variable Text` | `Segoe UI Variable Text` | `GlyphRunCaptured` |
| 𠮷 | U+20BB7 | `unresolved` | `MingLiU-ExtB` | `GlyphRunCaptured`（候选未覆盖、最终回退捕获） |
| 组合重音 | `e` + U+0301 | `Segoe UI Variable Text` | `Segoe UI Variable Text` | `GlyphRunCaptured` |

补充样本 `→` 最终为 `Segoe UI Variable Text`，指南针 emoji 最终为 `Segoe UI Emoji`；两者同样不把未在候选链中命中的情况误报为候选覆盖。报告中的 `FontActualGlyphRun` 已从旧的整体 `unknown` 改为逐样本 `TextFormatter.GetIndexedGlyphRuns` 结果。
