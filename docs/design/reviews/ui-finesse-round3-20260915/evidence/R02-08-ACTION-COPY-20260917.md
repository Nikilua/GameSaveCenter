## 任务边界

本项要求统一重试、重新加载、重新校验、下载到隔离区等动作名称，让用户从标签预判写入目标和结果，并避免把下载与恢复、上传与校验混在失败信息中。先查现有命令绑定：没有更换命令、DTO、Worker 协议或安全流程，只修正已经存在的生产入口和对应状态文案。

## 实现

- 存档旧入口 `ValidateCommand` 统一为“重新校验”，`LoadDetailsCommand` 在 Dashboard、Overview、Save Center 的四个入口统一为“重新加载详情”，并同步 ToolTip/Automation Name；重试状态仍使用“重试”，不把错误恢复动作伪装成普通刷新。
- 远端恢复第一步统一为“下载到隔离区并校验”，第二步继续为“快照并恢复”；说明、确认按钮和失效提示都明确隔离区、校验和恢复的先后关系。下载步骤不显示“恢复”，恢复步骤不显示“下载”。
- 云端队列把 `VerifyCloudTransferCommand` 标为“校验远端内容”，`RetryCloudUploadCommand` 保持“重试上传”，两者的 ToolTip、Automation Name 和 `CloudTransferStatusDto.GuaranteeLevelDisplay` 分别指向校验结果与上传结果。
- 生产可见的远端失败/状态消息统一使用“远端校验”，包括 Playnite 提示、CloudTransfer DTO、Worker 校验失败和远端暂存失效消息；协议内部的 `Check*` 状态名和 rclone 参数保持不变。
