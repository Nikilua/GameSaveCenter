## 结论

R07-03 在当前可控范围内已满足。核对最新生产布局后没有重建底栏、页面滚动、游戏选框或滚动条系统；现有 `AcrylicProductionShellView` 已把 `FooterSurface` 放在固定 36 DIP 底栏行，`PageHost` 位于主内容行，提示条和页面/表格/详情滚动区按各自现有所有权工作。本阶段只新增隔离 RenderHarness 的真实 WPF 短窗探针与合成 `MediaInboxPageHasMore` 夹具状态，用来把“可达”从静态源码条件提升为实际元素几何和滚动状态证据。

## 探针范围与行为

- `shortwindowprobe` 使用实际生产 `AcrylicProductionShellView` 及四类页面，在 `1040×700` 和更紧凑的 `1040×560` 逻辑 DIP、Light/Dark 两套主题下运行；共检查 16 个页面/尺寸/主题组合。
- Media 将页面滚动到末端，确认顶部 stale banner、内容区、底部 `LoadMore` footer 都有可见矩形且不覆盖 shell footer；Maintenance 在云端 surface 内确认 `加载更多` 可见；Task 在详情内滚到末端确认 `取消任务` 可见；Save 分别通过历史 stale banner 和 `保存策略` 目标元素 `BringIntoView` 验证短窗可达。
- 探针读取实际 `ActualWidth/ActualHeight`、元素相对 shell 的 `Rect`、`ScrollViewer.VerticalOffset/ScrollableHeight`、可见性和祖先关系，并显式检查页面内容矩形没有侵入固定 shell footer；不是只用 `Assert.Contains` 检查字符串。
- 首次 Save 负例发现“直接要求页面滚动到最大值”并不能证明按钮可达，因为 `保存策略` 不一定是文档末端；随后改为先回到顶端再对真实按钮调用 `BringIntoView` 并检查最终矩形。这次修正保留在探针中，避免把错误的滚动假设写成绿灯。
