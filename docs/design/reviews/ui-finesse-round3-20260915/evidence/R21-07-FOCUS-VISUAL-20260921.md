## 现有能力核对

本批先核对生产实现和既有证据，没有重建焦点或滚动体系：

- `GscSharedFocusVisual` 是生产共享焦点样式，提供 2 DIP、圆角和动态主题强调色；按钮、文本框、ComboBox、Tab、Expander 和列表相关样式继续复用它。
- 游戏选框仍是生产 `AcrylicProductionShellView` 的 `PickerOverlay`、`PickerList` 和既有滚动条/虚拟化设置；关闭路径仍调用 `ClosePickerAndRestoreFocus`，回焦原游戏选框。
- R09 已有实际 WPF 焦点环、失焦负例和错误视觉恢复证据；R05 主题弹层已有浅/深主题更新及窗口隐藏关闭证据。本批只补三种状态串联的生产 Shell 夹具。

## 行为证据

新增 `R21FocusVisualRegressionBehaviorTests.ProductionPickerKeepsVisibleFocusAcrossScrollThemeSwitchAndClose`，使用合成 2,000 项和隔离 STA `Window`：

- 打开生产游戏选框并完成布局后，搜索框实际取得键盘焦点且有共享 `FocusVisualStyle`；请求 `ListBox.ScrollIntoView` 后，末项容器被实际实现，且保留其焦点样式，不通过设置 `SelectedIndex` 提交选择或关闭弹层。
- 应用生产 `AdaptiveThemePaletteFactory` 的浅色/深色运行时资源后，强调色确实变化；焦点仍在可见搜索框，焦点样式仍存在，没有漂移到已隐藏控件。
- 通过生产游戏选框点击关闭路径后，`PickerOverlay` 变为 `Collapsed`，键盘焦点回到仍可见、可聚焦且有焦点样式的 `GameContextButton`。
- 已推送提交身份下串行重跑：R21 新增行为 `1/1`；既有 R09 焦点环 `2/2`；既有 R05 主题弹层生命周期 `1/1`；合计 `4/4`。三组分别运行，避免多个隐藏 WPF 窗口并行抢占桌面焦点。
