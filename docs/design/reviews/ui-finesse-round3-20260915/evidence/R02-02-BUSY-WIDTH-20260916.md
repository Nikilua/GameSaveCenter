# R02-02 忙碌宽度稳定证据

## 结论

R02-02 已满足。当前分支 `codex/ui-finesse-round2` 的代码提交为 `473cf3a`，是在核对前序 `4947539` 已有忙态模板后做的最小收口：没有把 main 的旧实现覆盖到当前分支，也没有新增业务服务或 DTO。

- 既有自定义 `ui:Button.IsBusy`、共享 `BusyIndicatorHost` 和不替换 `ContentPresenter` 的模板继续复用；Light/Dark 下忙态不会改变固定 180 DIP 按钮的测量宽度，也不会替换“全部备份”文本。
- `GscWpfUiButton` 现在从最近的生产 `UserControl.DataContext.IsBusy` 接入真实页面状态，因此当前 Acrylic 壳层和 Overview/Save/Media 等页面的派生按钮共享同一忙态入口；无 `IsBusy` 的设置/校对夹具回到依赖属性默认 `false`，旧 Dashboard 的本地绑定仍优先。
- `BusyOperationCoordinator` 为真实 `DashboardViewModel.RunAsync` 提供原子单槽：第二次进入直接拒绝；准备/动作失败或取消均经过统一 `finally` 复位，Dashboard 原有错误通知、取消文案和排队刷新语义保留。

## 既有能力核对与实现

前序提交 `4947539` 已实现 `NativeWpfControls.Button.IsBusy`、共享 indeterminate `ProgressBar` 和 `DashboardViewModel` 的 `IsBusy` 命令禁用；旧 `DashboardView.xaml` 的三个顶栏按钮也已绑定。核对当前实际可见的 `AcrylicProductionShellView` 后，发现其四个顶栏按钮和 extracted workspace 页按钮没有显式接收该状态，因此本项补在共享生产按钮基元，而不是复制页面级忙态代码。

本次代码改动：

1. `WpfUiProduction.xaml` 的 `GscWpfUiButton` 增加带 `FallbackValue/TargetNullValue=false` 的祖先 `UserControl.DataContext.IsBusy` 绑定；所有基于该样式的 Primary、Action、Context、MediaBatch、IconOnly 和 Redesign header 变体继续复用同一模板。
2. `DashboardViewModel.RunAsync` 委托给 `BusyOperationCoordinator`；`SetBusyState(false)` 先保留原 Trainer release 清理，再按原顺序释放 `IsBusy` 并触发 queued task/trainer/media refresh。
3. RenderHarness 的忙态边界文字更新为“共享生产壳层和 workspace style chain”，不再误称只覆盖旧 Dashboard header。

## 证据边界与安全范围

本轮行为测试使用 fake prepare/action、合成状态和隔离 STA WPF Window；没有启动真实 Playnite，没有写真实存档、媒体、云端或用户目录，没有删除真实文件，也没有外发诊断。共享绑定覆盖当前代码中的生产壳层/工作区样式链，但没有声称真实 Playnite 嵌入窗口已呈现。

已验证的是逻辑 DIP 测量、模板状态切换、命令槽稳定性、原子防重入和异常/取消复位；未验证真实 Worker/Playnite 命令的实际耗时、宿主输入时序、物理 DPI/跨屏、OS 键盘/IME、屏幕 presented frame、屏幕阅读器、ETW 或宿主帧率/大库性能。游戏选框、滚动条系统、命令 Binding、恢复保护、取消/错误语义和 net462 兼容未被本项破坏性改动。
