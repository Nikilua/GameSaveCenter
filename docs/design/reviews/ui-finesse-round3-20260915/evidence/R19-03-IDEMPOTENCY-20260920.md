## 1. 任务条件

R19-03 要求对已有写操作核对 request ID 与重试恢复，重点覆盖 UI 重复触发；响应丢失时不能重复执行，状态未知时必须明确显示，不能擅自重试恢复或删除。

本项没有重建写服务。审查当前实现后确认，生产链路已经满足这些边界：

- `src/GameSaveCenter.Contracts/IpcEnvelope.cs` 为每个 IPC envelope 提供 `RequestId`，`IpcRequestSemantics` 将备份、恢复、媒体写入、分类、策略、云端、设置、保留、镜像、任务取消和工具写入归为 replay-protected 请求。
- `src/GameSaveCenter.Worker/Ipc/NamedPipeServerService.cs` 对 replay-protected 写请求使用持久化 ledger claim；同 ID 同指纹只执行一次，已完成请求重放原响应；不同 payload/type/protocol 返回 `REQUEST_ID_CONFLICT`；执行中返回 `REQUEST_IN_PROGRESS`，Worker 重启中断返回 `REQUEST_INTERRUPTED`，均不再次提交业务写入。
- `src/GameSaveCenter.Playnite/Ipc/WorkerIpcClient.cs` 在超时或管道丢失且请求可能已接收时，只用同一个 envelope、同一个 `RequestId` 复核；不会创建新 ID。取消保留“结果可能未知”语义，不以新 ID 自动重试。
- `src/GameSaveCenter.Playnite/ViewModels/BusyOperationCoordinator.cs` 以原子门拒绝第二次 UI 触发；`DashboardViewModel` 的生产写命令继续使用 `!IsBusy` 与共享 `Run(...)`，异常/取消在 finally 恢复忙状态。
