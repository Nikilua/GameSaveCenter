# Round4 交付快照与退出条件

## 范围

当前用户授权覆盖 `UI_FINESSE_ROUND4_64_TASKS_2026-10-18.md` 的 64 项计划。`AUTONOMOUS_BACKLOG.md` 用于选取一个可执行子任务；`PROPOSED` 表示该项尚未完成已有能力对照或依赖准入，不要求用户重复授权计划内工作。计划外的新产品想法须另行明确准入。

## 每个小批的单次快照

每个独立小批完成时，集中更新一次 `ROUND4_STATUS.json`、生成 `ROUND4_PROGRESS.md`、追加 `WORKLOG.md` 与必要的项目记忆，然后提交该批实现和证据。快照要说明：

1. 任务 ID、实现提交和可复查证据；
2. 实际运行的验证、结果与未覆盖范围；
3. 已满足的依赖、仍阻塞的前置条件；
4. 下一项可执行任务，或明确说明为何当前没有可执行项。

纯 CI 成功结果不引发额外记录提交，按根 `AGENTS.md` 中 S07-04 规则处理。若实现提交与记录实现哈希需要两个提交，第二次只补精确哈希与生成账本，不重复记录验证结论。

## Round4 完成条件

- `ROUND4_STATUS.json` 的 64 个 ID 与计划一致且唯一；账本链接、证据路径及生成区域检查通过。
- 每项都进入 `已验收`、`已满足` 或 `不适用`，实现、受控验证和宿主验证分别如实记录；还需要的宿主、设备、权限或外部证据未完成时，Round4 不能宣告完成。
- 每项有可复查证据和边界说明；历史失败、未检查或被拒权限不得改写成通过。
- 所有实现提交、证据和当前代码身份相互对应。含未通过 UI 门禁的 S00-02 改动时，不推送该分支。

满足这些条件后，写一次最终快照并明确结束 Round4 工作；不继续从归档或仓库扫描中寻找新需求。用户这次要求的 64 项尚未完成，因此单个小批完成不等于总目标完成。

## 没有当前可执行项时

先在已授权的 64 项范围内检查独立任务及其依赖。如果都需要尚未具备的 SDK、宿主、设备、权限或用户提供的同次证据，就记录真实阻塞、具体重试条件和下一项解锁条件；不重试拒绝的探测，不把 `PROPOSED` 解释成已授权范围之外的任务，也不通过发明新需求填补空档。出现前置变化后继续既定计划；只有超出本计划的范围才需要新的授权。
