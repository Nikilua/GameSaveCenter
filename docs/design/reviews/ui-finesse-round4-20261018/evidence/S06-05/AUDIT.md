## 计划验收

清单操作打开既有详情/预览，用户处理后可手动标完成；完成标记不冒充备份/校验成功，取消业务操作不自动标完成。

## 现有能力核对

- S06-01 的 `WorklistItemRecord.IsManuallyComplete` 已纳入克隆和归一化，可随插件设置持久化；S06-03 `WorklistBrowserEntry` 只投影为“未完成”或“已完成（手动）”，表格为只读。
- 浏览器只有续接、刷新、重排和移除命令，没有修改 `IsManuallyComplete` 的用户命令，也没有单项完成/撤销入口；现有测试只验证字段投影与克隆，不验证用户能改变状态。
- S06-04 已按稳定 ID 将存档、媒体、任务和校验问题带到各自既有详情。续接只导航；备份、恢复、校验建议、任务重试仍由用户从原业务页单独发起。
- 现有业务命令不会写入工作清单的手动完成标记。取消和失败也不会自动改写该字段，因此没有“取消后自动完成”的等价能力或回归入口。

## 结论与准入范围：READY

S06-01 至 S06-04 依赖均已完成。保存字段和只读展示虽已具备，但缺少逐项人工转交闭环中的可逆手动完成操作，不能将字段存在视为功能已实现。

增加只作用于唯一选中条目的显式动作：未完成时显示“标记为已完成”，已完成时显示“恢复为未完成”。写入 `IsManuallyComplete` 并复用插件设置持久化/失败回滚；保留同一条目的解析状态、稳定 ID、顺序和备注。状态文案必须明确这是人工跟进记录，不表示备份或校验成功。续接、打开预览、业务命令成功/失败/取消均不得自动切换此标记；完成后可直接继续处理下一条。动作可立即撤销，不触碰源业务对象，也不需要 SDK8、Playnite 宿主或外部设备作为前置条件。
