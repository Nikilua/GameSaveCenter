# S06-01 工作清单契约能力审计

日期：2026-10-21

审计基线：`dc696fb0`（S05-08 已推送）

## 已有相邻能力

- `Settings/RecentAccessRecord.cs` 只记录最多 8 个“游戏 ID + 工作区 + Tab + 时间”，按游戏去重；它用于回到最近访问位置，不允许用户主动加入异类对象，也没有名称、条目备注或人工完成状态。
- `FindingTriageResolver` 按当前健康检查结果分组展示问题，结果是临时解析值，不是用户维护的清单。任务中心保留的是实际后台业务任务及其运行状态，不是人工待办标记。
- 媒体比较意见、保留情景和已保存筛选视图分别有自己的对象模型，但都没有清单 ID/名称、跨业务对象种类的稳定引用、条目备注与手动完成状态；它们的生命周期和语义不能直接当工作清单使用。
- 在 Contracts、Playnite Settings/ViewModels、Worker 和现有测试范围内检索 `Worklist`、`Checklist`、`Todo` 及相邻模型后，未发现同等的可持久化用户对象清单契约。

## 准入结论：READY

S05 顺序已完成，S06-01 是本组首项。没有前置 S06 数据或页面改动依赖它。建立仅含清单元数据、对象种类/稳定 ID、短备注和人工完成标记的设置模型；用有界归一化处理条目数、清单数、名称/ID/备注长度，按“对象种类 + 稳定 ID”去重。契约不包含运行时 DTO、文件内容/路径、认证信息、命令参数、预览句柄或操作授权。

如果底层 ID 只在其父对象内唯一，调用方需将父 ID 编入稳定 ID；S06-02 再为各产品入口确定映射。此项不接入设置持久化、UI、导航或业务动作，留给后续依赖项。
