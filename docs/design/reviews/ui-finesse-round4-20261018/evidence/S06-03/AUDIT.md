# S06-03 清单浏览整理能力审计

日期：2026-10-21  
审计基线：`85400645`（S06-02 已推送）

## 等价能力核对

- `WorklistDefinition` 只提供有界保存、归一化和加入去重；目前没有清单浏览页、活动清单选择、搜索/分组视图、条目重排或移除命令。
- `RecentAccessRecord` 是按最近访问排序、最多 8 条的系统生成入口状态。它不允许用户任意添加/分组/排序，也不包含备份、媒体、任务和校验问题等异构对象引用。
- `FilterPresetDefinition` 最多保存 32 组任务或媒体筛选条件。它保存的是查询参数，不是用户待办对象；应用预设不能浏览、重排或移除跨页面对象。
- `FindingTriageResolver` 只对当前校验结果按影响分类生成派生分组；不会持久化用户顺序或备注，也不涵盖其他类型。
- 任务队列、存档历史、媒体收件箱和路径校验各自已有局部搜索/过滤/业务操作，但都只作用于该页面当前数据集。将这些局部筛选视作通用人工清单会漏掉其他对象类型，并使“移除条目”误触发源对象操作的风险变大。
- S06-02 加入的清单引用只持久化种类和稳定 ID。当前还没有按 ID 解析当前对象并显示有效/失效的清单投影；不能以 `Items` 中存在格式正确的 ID 伪称源对象仍然有效。S06-06 后续可扩展名称、归属和权限变化后的刷新，但 S06-03 必须先定义“当前数据尚未检查”与“已确认找不到”的区别。

## 缺口与准入结论：READY

计划依赖 S06-01/S06-02 均已完成。S06-03 是明确的新跨类型人工清单能力，不等价于任务筛选预设、最近访问、当前问题分组或各页面内部列表。准入范围是新增清单浏览与整理表面：选择清单，显示条目种类/稳定键/手工状态/解析状态，提供有界搜索、按类型/状态分组、键盘可达的重排和单项/批量移除。移除仅更改清单记录，不删除、恢复、忽略或修改源对象；批量操作先显示确切条数并要求确认。

解析状态须保守：能由当前明确完整的源快照精确匹配时显示“可定位”；只有完成了对应来源的权威 ID 查询后才能显示“未找到”；未查询、数据不完整或权限不足时显示“待刷新/无法检查”，不能误标为失效。S06-03 先复用可用的 ID 查询/当前完整快照；若缺少权威只读解析入口，将在该项实现前明确登记依赖，不以名称或路径猜测对象。S06-06 再处理后续重命名、删除、归属变化和权限变化刷新。

审计未运行构建或测试，也未修改产品代码。
