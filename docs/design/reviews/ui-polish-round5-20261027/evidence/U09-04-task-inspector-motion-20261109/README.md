# U09-04 task inspector motion probe (2026-11-09)

## Scope and source identity

This is a focused supplement to the unresolved U09-04 performance comparison. It exercises the compact task detail inspector at 960×640 DIP with the same deterministic bound task rows, both themes, and 12 open/close pairs per theme. It does not replace the existing TaskGrid scroll, cumulative allocation, or host-presentation measurements.

The production source trees came from `git archive` of U00 `5d0a2448d6315af61571d0d3fbecfd902e5344fc` and current baseline `0258ab3513c7d1bc95b8b622eead42a0fab30a76`. For a shared probe, `Program.cs`, `FakeDashboardData.cs`, and `FakeSampleClock.cs` were copied from the current working tree into each temporary snapshot. The U00 fake DTO fixture omits three `Source` initializers unsupported by that older DTO. These are test harness changes only; production files under `src/` remain the respective archived revisions. The shared `Program.cs` SHA-256 and both archived `TaskCenterView.xaml` and harness executable hashes are in [source-hashes.json](source-hashes.json).

The harness assembly receives the archived source SHA through `GscBuildCommit`. Its report now prefers this explicit build identity over the enclosing checkout's `git rev-parse`. Snapshot folders are not Git worktrees, so reports say `WorkingTreeClean: unknown (source root is not the Git worktree)` instead of attributing the outer checkout state to a snapshot. The hash file is the byte-level identity evidence; the commit field identifies the production baseline, not a claim that the shared harness source is byte-identical to that commit.
