# 第六轮：可见的界面与动效升级

日期：2026-11-13；规划基线a31a733e。用户在质量收口后明确提出更高视觉目标，本轮是新设计迭代，不是把旧任务重新标为未完成。此文件仅为实施计划，不代表效果已实现。

## 目标与边界

让用户在同数据对比中直观看到页面更整洁、重点更突出、控件更协调、动作更连贯。不能只修改测试、文档、几个不可辨认的色值就宣布视觉升级完成。也不要求为了制造差异而改掉已经优秀的部分。

先完成存档页整页示范，再推广任务、媒体、概览和设置。以Demo-first为方向；Demo源缺失时明确记录并沿用当前生产资源，不伪造参考。WPF技能只作质量依据。允许重新组织页面层次和共享控件；保留当前游戏选框、现有滚动条系统、全部真实命令/绑定、恢复安全语义、取消/错误处理、虚拟化、键盘/UIA和Playnite兼容。不引入WebView或新视觉框架，不恢复撤销的今日工作台。

## 设计方向

- 页面采用清晰的标题区、上下文区、操作区、内容区、详情区；主要动作明确，次要动作收敛。减少重复卡片边框和重复状态文字，不能删除功能或把重要操作藏起来。
- 中英文沿用现有字体回退体系，标题/正文/辅助信息层级稳定。以现有字号为起点，改善字重、基线、行距、数字单位和图标比例，不靠全局放大字号制造差异。
- 浅色要清爽、有表面层次；深色要柔和但文字清楚。强调色集中用于主操作与选中状态，避免满屏蓝块、重阴影、玻璃和渐变。动态主题色统一使用共享令牌。
- 按钮、输入框、页签、列表、浮层形成一个控件家族。对齐和状态覆盖优先于装饰；选中、hover和键盘焦点同时出现仍可区分。
- 动画用于解释变化：页面切换轻、详情进出清晰、按压反馈及时、加载交接稳定。快速反向操作从当前视觉值接续，不排队、不闪回、不等动画结束才执行真实命令。

## 交付节奏

1. V01～V04形成可复现基线和视觉方案；先查当前源码去重，记录本轮具体要改变什么。
2. V05～V12完成存档示范页及共享原件。必须先交付可观看的示范对比，再大范围迁移；默认由实施者依据下方质量标准完成内部评审，不额外等待用户批准。用户给出意见时优先调整。
3. V13～V20完善动态体验，再V21～V24推广页面；每批2～4项，不一次改所有模板。
4. V25～V28贯穿每批，最终提供明确可查看的前后效果包和未验边界。

## 不能省略的验收要求

同一页面前后必须同数据、主题、尺寸、字体环境和缩放；保留原图，另外可做并排对比，不能通过改变数据密度或裁剪掩盖问题。截图来自实际生产XAML渲染，不能用概念设计图冒充产品。主示范至少有常规页与详情打开两类状态，双主题各一套；后续只保留必要代表样本，避免截图泛滥。

动画必须提供实际运行的动态证据，静态截图不能证明流畅。受控WPF、离屏采样、Playnite真实前台与物理输入分别标识。能看出改动不等于改得更好：逐项检查主次、对齐、可读性、反馈、连续性、空间利用；无差异或负向差异须解释并修正，不能以改动行数验收。

每个源码/资源小批完成相关编译与风险行为检查；按UI_CHANGE_GATE运行validate-source.py、WPF静态检查及页面改动render-qa。最终候选先提交、冻结跟踪文件，使用实际GameSaveCenter-一键构建安装运行.cmd转GameSaveCenter-Run.cmd完成build/test/publish/package/隔离安装/启动，记录最外层直接退出码0、SDK、源码和程序集身份；scripts/build.cmd按实际职责独立验证。沿用已授权隔离配置，不访问真实存档/配置、不真实恢复/删除/云写。不能用SkipTests、旧提交或单独dotnet build冒充全链。

推送后查精确提交所有适用GitHub jobs，含当前SDK基线和SDK10复核；失败定位修复，不关闭检查、不扩大skip或反复追绿。既有required-checks/ruleset403不重复探测，记录名单待验，不把它说成已运行CI失败。纯文档仅静态/链接校验，不为文档CI通过循环补记录。

每阶段核对产物归属、规范化根内路径、重解析点、运行占用和证据引用后，使用PowerShell Remove-Item -LiteralPath -Recurse -Force清理artifacts/与.tmp内本阶段无用输出。保留当前必要构建/包、审计、失败诊断与有效引用，记录清单/空间；不清用户TRX/TestResults、未知文件或其他任务产物。清理被拒不得换工具绕过。
