## 第 1 周 · 补齐宿主验收，追踪新档提示（预计 2–4 天）

1. **建立可重复进入的带数据宿主。** 复用已走通的隔离配置或其独立副本，先核对当前程序集、Worker 与私有管道，再进插件首页。固定游戏 ID、同名游戏通知、两个目录的差异、三张可辨识的截图和一条离线媒体。保留小型种子和必要证据，每轮可重新生成临时 profile。
2. **一次走完 A/B/C。** 在同一集成候选用键盘展开差异目录并交换 A/B；只标记当前游戏可见通知已读，再核对另一同名游戏和全局通知；把第 3 张截图移至首位并导出，核对焦点和 PNG 顺序。采集有数据的窗口图、操作结果、显示比例和提交身份。已完成的备份恢复故事无需整段重跑。
3. **定位新档从 Worker 到历史页的延迟。** 同时记录任务完成、版本可查询、插件收到事件或刷新、列表计数与提示更新。分别在第一页顶部、第二页选中旧档、切换到另一游戏时触发。用生产支持的入口区分插件内与后台生成版本的刷新约定。若提示漏发或晚于正常刷新周期，定点修复并加入对应回归。连续两次新增应准确计数，重复刷新不重复提示，旧档焦点不动。若属明确的刷新策略，交付实测时序与适用范围。

## 第 2 周 · 让常用页面在窄窗里更好读（预计 4–6 天）

4. **画廊作为视觉样板。** 现有 760×640 浅色合成图里，上方大面积留给单行卡片，下方每个已选项重复序号与三枚方形操作键。[查看样本](../../artifacts/player-followup-c-38ecae44/focused-tests/progress-recap-captures/progress-recap-Light-760x640.png)。先用真实图片做两个布局样本：宽窗中让截图占更多空间，窄窗先读标题与图片，次要设备信息跟随详情。比较玩家找到指定画面所需的滚动和操作，选优后落生产。0、1、3、9 项、长中文标题和离线图都可读；选择、排序和键盘入口仍可达。
5. **通知页给阅读结果留出高度。** 以实际完整行数作为基线，把范围、级别、时间、搜索和批量标记按频率排布。先检验当前窄窗布局；只有减少遮挡、换行或滚动的方案才迁移。用 980×640 和 1040×700、长游戏名与无选中游戏验证，保持已有 1040 窗的 3 行回归下限。批量操作发生前能看清作用范围。
6. **长路径和危险操作的阅读顺序。** 在比较与恢复详情中抽样同名文件、长根目录、长设备名。让玩家先分清游戏、版本方向、目标和主要变化，再读次要元数据。完整路径可复制、键盘可打开详情，缩略显示不得隐去辨别两个目标所需的信息。恢复确认保留原命令和保护语义。只推广已在样板证明有益的共享样式。
7. **焦点与动效连续性。** 只处理三个高频动作：列表到详情再返回、回顾图跨行换位、搜索或筛选后定位结果。真实输入快速反转，中途切页、改变窗口宽度，检查最终焦点、读屏序号、选择与可见行。共享短动效只作用于移动项，Reduced Motion 与高对比度走静态等价反馈。没有发现问题的动作保留原实现。

## 第 3 周 · 量清楚哪里在等，再做小而有效的提速（预计 3–5 天）

8. **四条用户路径的速度基线。** 固定机器、渲染方式、数据和包身份，测打开历史到首批可操作、全历史搜索到正确结果、打开画廊到首屏可用、生成 9 图预览。用百条与万条合成历史，有图、离线图各一组。冷启动与热态分开，记录重复次数、原始值、中位数与长尾，分出 IPC、SQLite、图片解码和 UI 线程耗时。宿主画面与离屏计时分别报告。
9. **封面慢盘与取消。** Worker 在读取封面记录时检查文件存在性，画廊每页最多取 36 个版本。构造受控慢 I/O 和离线样本，测数据库读取、首张可见、切游戏后的过期工作及峰值并发。确认瓶颈后再考虑释放 reader 后探测文件、可见项优先或复用结果；离线、重新归类、取消和同 ID 跨游戏的语义逐项回归。[封面读取](../../src/GameSaveCenter.Worker/Persistence/SqliteStateStore.BackupCovers.cs)
10. **9 图预览时保持可操作。** 图片异步获取后，位图合成目前在 UI 回调中执行。测生成时的最长 UI 调度间隔、内存峰值与连续排序的废弃请求。确有可感知停顿再调整解码预算、合成调度或复用。重复前后配对测量；结果应超出基线自然波动，且预览与 PNG 一致、切换游戏不会显示旧图。[预览入口](../../src/GameSaveCenter.Playnite/ViewModels/DashboardViewModel.ProgressRecap.cs) · [缩略图计数器](../../src/GameSaveCenter.Playnite/Converters/AsyncThumbnailLoader.cs)

## 第 4 周 · 长会话稳定性与发布候选（预计 2–4 天，可按证据提前结束）

11. **模拟一次晚上的反复使用。** 在隔离数据里循环执行搜索、开合详情、换游戏、浏览图片、取消预览，空闲后复测。复用现有 soak 和缓存计数，跟踪工作集、托管存活对象、句柄、解码并发与等待任务。以稳定平台期和重复回落为依据；持续增长才定位引用链，避免把正常缓存预热当泄漏。
12. **Worker 中断后恢复使用。** 在隔离环境只对已确认身份的测试 Worker 模拟读取中断，验证页面能恢复、旧结果不会写回别的游戏、重复点击不会重复提交。恢复写入等高风险中断复用已有隔离夹具。只补交互边界缺口。
13. **冻结候选并决定是否结束。** 汇总实机故事、同数据前后截图、性能变化、剩余限制。遇到门禁失败先保留根因诊断；若 UI 指标无收益或性能差异落在噪声内，保留结果、结束相应优化。后续功能以玩家反馈另行立项。
